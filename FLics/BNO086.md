# FLics: BNO086 over I2C

Target: ESP32-C6, ESP-IDF v6.1. This adapts the existing full FLics application;
the pump, ToF and Jetson UART code remains present. It is not an ESP32-S3 build.

Branch: `josh_ripple`, based on Shaurya's merged PR #4 (`cb751ae`). Preserves
the teal palette (top `#9AF3EC`, middle `#0FA3AB`, bottom `#086A79`), fixed 60%
display fill, tilt sensitivity 1.4, splash thresholds 10.8/16.0 m/s^2, and the
updated dispensing/cup-removal behavior. Only the IMU integration is adapted.

## Wiring

| BNO086 breakout signal | ESP32-C6 |
| --- | --- |
| SDA | GPIO22 |
| SCL | GPIO23 |
| GND | GND |
| Power | Regulated supply appropriate for the exact breakout; verify its documentation |

Use 3.3 V I2C logic and external SDA/SCL pull-ups to 3.3 V (often already on the
breakout). Configure the breakout for I2C, not SPI or UART. The adapter tries
7-bit addresses 0x4A and 0x4B. Do not use the old BNO055 address 0x28.
INT and RESET are not required by this polling/soft-reset adapter; keep the
breakout's reset and interface-selection pins at its documented default levels.
No sensor power should come directly from a 12 V rail.

The LED data connection remains GPIO21. These are GPIO numbers, not XIAO D-labels.
The breakout model has not yet been supplied, so power-pin labels and interface
jumper positions must be checked against that board's instructions.

## Behavior

- CEVA's SH-2/SHTP library replaces the BNO055 register driver. The exact upstream
  revision is recorded in components/ceva_sh2/UPSTREAM.md.
- Requests the calibrated accelerometer at 50 Hz, including gravity, in m/s^2.
  This is not raw ADC counts or gravity-subtracted linear acceleration.
- Keeps FLics' existing sensor-frame axes and horizontal acceleration = -Y.
  Align the new breakout's axes with the old sensor, or deliberately change the
  mapping in fluid_task after testing its physical orientation.
- Uses 100 kHz I2C with clock-stretch tolerance, software reset, product-ID query,
  and a required first acceleration report before startup is declared successful.
- A dedicated task owns SH-2 calls. A one-element FreeRTOS queue publishes the
  latest complete sample to the animation task; samples older than 500 ms are
  rejected. A sensor reset invalidates the sample and re-enables reports.
- Missing IMU: five initialization attempts, then the existing red error blink.
  Runtime stale data pauses simulation updates and emits a diagnostic warning.

## Build

Activate ESP-IDF v6.1, then from this directory:

```powershell
idf.py -B build-bno086 build
```

The supplied sdkconfig targets esp32c6. Use a fresh build directory rather than
the repository's checked-in build directory, which contains another user's paths.
The dependency manifest now only requires espressif/led_strip; the SH-2 component
is vendored locally. The upstream update already resolves the old duplicated
rendering and cooldown lines.

## Hardware acceptance checks (not yet performed)

1. Confirm regulated power and correct I2C wiring before reconnecting peripherals.
2. Check startup for a product/firmware ID and the 50 Hz acceleration message.
3. With the board still, acceleration magnitude should be roughly 9.8 m/s^2;
   tilting should move the fluid in the intended direction.
4. Disconnect sensor power: no stale motion should continue after 500 ms.
5. Restore/reset the sensor: verify the reset/report-restoration log and resumed
   animation. If polling cannot recover a particular board, power-cycle it.

BNO08x I2C clock-stretch behavior can be sensitive to ESP hardware and wiring.
A successful build does not establish electrical compatibility: report delivery
and reset recovery must be verified on the actual BNO086 breakout. If I2C remains
unreliable, an INT-assisted transport or SPI is a separate hardware/driver change.
